A Z boson lives for a moment and then falls apart into two leptons. Those two leptons still carry its mass between them. Add them together, take the mass, and plot it.

Objective

Find the peak, and read its position within ±2 GeV of 91.2 GeV.

Your analysis Board — typed columns, drag or click to connect

Board lays your analysis out in five typed lanes — Data, Multiplicity, Selection, Observable, Histogram — the same order a pipeline runs in. A new node joins the bottom of its own lane; drag a node's title bar up or down (or focus it and press the arrow keys) to reorder it within that lane. To connect two nodes, either drag from an output port to an input port, or click one output port and then one input port — both work here. The result figure lives inside the graph itself, as the Histogram lane's own content.

            What Board is, and what it gives up

            • Persists {column, slotIndex} per node, plus the edge list. The board container (#graph) carries one attribute, data-ui, holding a JSON object shaped { nodes: [{id, column, slotIndex}], edges: [[from, to]] }. A node's column is fixed by its kind — DataSource always lands in lane 0, Histogram always in lane 4 — and is read back from wherever that node's element actually sits in the live DOM at persist time, not carried as separate mutable state that could drift from the render. slotIndex is that node's position within its own lane's list, likewise read from DOM order. Node kind itself stays on the node's own element (data-node-kind), the same place Beamline and Bench put it, because kind is analysis content the run payload carries, not a layout fact. verify.py --board reads this attribute after a real slot move, not just at load, so the claim covers a moved node, not only a spawned one.
            • Both connection gestures work, plus a keyboard path. An output port carries a pointerdown listener for drag-to-connect (drop on an input port to finish, the same mechanics as Bench) and a plain click listener for click-to-connect (click an output port to arm it, then an input port to finish, the same mechanics as Beamline). A native <button> already turns an Enter or Space keypress into a synthesized click, so the same click handler that answers a mouse click also answers the keyboard, with no separate keydown listener needed for it. Bench refused click on purpose, and Beamline refused drag on purpose — Board is the one style asked to accept both, so both are wired deliberately here rather than one falling out as an accident of a shared handler.
            • The plot lives inside the graph, as the Histogram lane's own content. Every Histogram node's card carries a .plot-embed figure (data-wf="plot") sized at the reference figure's own fixed 650×460 CSS px, the intrinsic size D-003's plot.html renders at and does not reflow below. That size does not fit a 768px-wide viewport once the other four lanes sit beside it, so the whole board scrolls horizontally inside its own wrapper (.board-wrap, overflow-x: auto) — the same device Bench's canvas and D-003's own figure already use — rather than the page body ever gaining horizontal scroll.
            • No inline style= attribute, anywhere. A node's lane and slot are both facts about where its element sits in ordinary DOM flow — which <ul> it is a child of, and at what index — so placing a node needs no coordinate and no style= at all; reordering within a lane is plain insertBefore/appendChild. The one thing this style still draws as geometry rather than flow is the connector between two ports, since a drawn line needs endpoints to draw between: those live in the edges layer's own SVG <path d> and the overlay <svg>'s own width/height attributes, computed from each port's live position and written as plain SVG geometry attributes, never a style property — the same category of exception Bench's <foreignObject x y> already makes for the same reason.
            • The trade this style makes, on purpose. Board gives up Bench's free spatial arrangement — a node cannot be dragged next to an unrelated node just because the student wants them near each other — and gives up Beamline's single-glance simplicity, since five lanes read as more machinery than one rail. What it buys instead is a structure that answers a question neither of the other two can: which pipeline stage is this node in, at a glance, from its column alone, independent of the order it happened to be added — the same {column, slotIndex} shape the real run payload's own "ui" object would need to carry, whichever style ships.
            • Locked node kind. The palette's final tile is not one of the 8 addable kinds — it stands for a node type a later mission unlocks, shown so a student can see it is coming. It carries no port, no click handler, and no tab stop, so it cannot be reached as an active control by keyboard or by mouse.

            Nothing on this page ships; it exists to be compared against Beamline (D-004, single rail, click-to-connect) and Bench (D-005, free canvas, drag-to-connect) at the D-007 checkpoint. See verify.py --board for what is actually measured about this rendering, rather than claimed here.
