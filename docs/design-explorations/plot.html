Two open questions for the checkpoint i

  • Legend placement. Reference parity puts the framed legend inside the axes, upper-right — that is what is built here, at every width this page is screenshotted at, because the figure keeps a fixed intrinsic size rather than reflowing (see verify.py --plot for the measured legend box against the measured plot area, at each width). That box sits over the Z peak in a 0–150 GeV range, which is the worst possible place for it to sit. My recommendation, if asked to decide: keep the framed inside-axes legend as the default, matching the convention students will meet in real papers, and add a second legend position — outside the axes, like the cutflow's — that a mission page can opt into once the figure is embedded somewhere narrower than this exploration's fixed frame allows. I did not build that second position; changing the anatomy was not this task's job, reporting the measurement was.
  • Sample colour mapping. Both schemes below are wired up for real, not mocked — the toggle button above the histogram swaps the data-palette attribute on <body>, which is the only thing that changes; nothing re-renders. tab10 (parity) assigns colour by sample draw order, exactly as engine/plotter.py and engine/cutflow_plotter.py do — faithful to the reference, but it means X1's colour is not fixed: add a fourth sample ahead of X1 in draw order in a later mission and X1's hue changes with it. Frozen per-sample map fixes X1 (the signal across missions 1–3) to the reserved vermillion accent — an explicitly sanctioned use per docs/design-brief.md §7 — and gives X2 and X3 hues that do not move as the roster grows. My recommendation, if asked to decide: frozen, because a student re-encountering X1 in mission 2 in a different colour is a teaching bug dressed as a cosmetic detail. Not my decision to make here.
