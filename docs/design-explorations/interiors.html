FCE-site design explorations

What is inside a node

A node today has exactly one configurable property — subtitle, whose value is the literal string "not configured yet". This page is the checkpoint that settles what replaces it: what a student sees when a node sits closed on the canvas, and what they see once they open it, for each of the seven kinds the palette will ever place. docs/design-brief.md §4 is explicit that this is not inherited from the reference desktop tool's dense fixed property grid — this is the design question that grid answered, asked fresh for a 15–18-year-old who has never opened a physics tool before.

Two complete interiors follow, each rendering all seven kinds in both states side by side. Read both, then the recommendation at the bottom.

Recommended

Flyout inspector

The node itself never changes size. Opening a node raises a panel attached to it — visually hinged off its bottom edge, like a card flipped open on the bench — that holds the guided form. Closing it collapses the panel again; the node's own footprint, and every port and edge attached to it, are untouched by opening or closing.

What this adds to the run payload: nothing to the node's position or size — {id, x, y} (bench.html:289-292) is unaffected by open/closed state, because the flyout is drawn as an overlay, not a resize. Each node instead gains one config object (the guided field values, or the raw expression string) and one open boolean, and the latter is exactly the kind of layout fact docs/design-brief.md §4 already assigns to the ui object the engine never reads, alongside coordinates.

Histogram

Adds config: {bins, min, max}; the axis label is read off the connected Obs node rather than typed, so it cannot drift from what actually feeds it.

Alternative

Inline grow

Opening a node grows the node card itself, in place, to hold the guided form directly beneath its title bar. There is no separate panel — what you see is the whole node, just taller. Closing it shrinks the card back down.

What this adds to the run payload: the same config object and open flag as the flyout, but here open also has to move whatever sits below the node in Bench's free canvas — a taller node lengthens the edges leaving it and can now overlap a node placed close underneath, which the flyout does not do because its panel never displaces a neighbour node's own {x, y}.

Recommendation

Flyout inspector. Both options carry the same guided fields, the same dual guided/raw form for Selection, and the same payload shape — the actual research question this checkpoint answers is where the interior lives, not what it asks for, and on that question the two options diverge in a way that matters for D-010. D-010 (the three-region shell) is blocked on node size deciding how wide the palette has to be; a node whose own footprint never changes between closed and open gives that task one fixed number to design against. Inline grow gives it two, and a taller open node on Bench's free canvas (bench.html:157-186) can now overlap whatever a student already placed underneath it, which a canvas that persists free {x, y} positions has no mechanism to prevent or resolve. The flyout's panel is layered on top of the canvas instead of displacing anything on it, so opening a node to configure it is never the action that breaks a layout a student already built.

The cost accepted: a flyout is one more visual layer than a card that simply grows, and it needs its own hinge affordance to read as attached to the node it belongs to rather than a floating popover. That cost is a rendering detail for whichever role builds the shipping version; the node-size question it protects is not.
